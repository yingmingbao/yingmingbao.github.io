一、结论摘要（Executive Summary）

综上研究，主流语音交互界面在「端侧唤醒 + 云端理解」的混合架构上高度趋同，但在模型部署位置、生态开放度与商业模式上分化明显。核心结论如下：

  1. 架构趋同、部署分化：所有主流方案均采用「端侧低功耗唤醒 + 云端（或端侧大模型）ASR/NLU/TTS」的两段式结构。Google、Apple 将越来越多 NLU 与部分 ASR 下沉到端侧（Pixel Titan M2 / Apple Neural Engine），Amazon、百度、腾讯仍以云端为主，讯飞走「端云一体」路线。
  2. 麦克风与远场是硬件护城河：Amazon 以 7 麦克风环形阵列 + 波束成形定义了远场标准；小度/小米带屏音箱、手机多麦（如部分 Android 机型双麦波束）依赖麦克风阵列 + AEC + 降噪。阵列设计与 DSP/Codec 是硬件壁垒。
  3. 流式识别成为标配：Google（gRPC 双向流 Assist RPC）、腾讯云 ASR（实时流式、自动断句）、讯飞均支持「边说边出字」；RNN-T / Transformer 端到端模型取代传统 HMM，首字延迟可压至数百毫秒。
  4. 市场见顶且高度集中：中国智能音箱 2024 年销量 1570 万台（同比 -25.6%），连续四年下滑，小米/百度/天猫合计 96.2%（洛图科技，S1）；全球由 Amazon、Google、Apple 主导。语音入口正从「独立音箱」向「手机/车载/AI 助手」迁移。
  5. 输入法赛道格局不同：第三方输入法由搜狗、讯飞、百度、微信输入法主导（合计约 84%，S3/S4 口径不一），语音输入是 AI 输入法的核心功能，讯飞以语音技术见长（74 语种/方言免切换，S3）。
  6. 隐私与合规成关键变量：Apple 以端侧 + Private Cloud Compute 主打隐私；Google/Amazon 提供语音删除与本地处理选项；中国受《个人信息保护法》《数据安全法》约束，录音与生物特征处理需显式授权。
  7. LLM 重构交互范式：Alexa+（2025，调用 Nova/Claude）、Apple Intelligence（Siri）、Gemini、文心/小度、星火/讯飞、元宝/腾讯均将大模型引入语音链路，推动从「指令式」向「对话式、多模态」演进。
  8. 经济性上，硬件多为「引流/微利」，价值捕获来自生态服务（电商导流、广告、内容会员、云 API、企业方案）。成本结构中云端推理与内容分成占比上升，端侧 NPU 算力成本下降使端侧化可行。
一句话结论：语音交互的「接口层」已商品化、趋同；真正的竞争在「模型能力 + 生态闭环 + 隐私合规 + 单位推理成本」四角，而这四点正被大模型与端侧算力同时重写。

二、整体架构：唤醒、麦克风阵列、VAD 与端侧唤醒模型

语音交互系统的第一性问题是如何在极低功耗下「随时待命」却不泄露隐私。各家的共同解法是：在端侧常驻一个极小的唤醒模型，只监听唤醒词；命中后才启动高功耗的录音与云端（或端侧大模型）理解链路。

2.2　麦克风阵列与波束成形（Beamforming）

远场（3–5 米）语音的关键是抑制混响、噪声与回声，突出说话人方向。核心手段是麦克风阵列 + 波束成形 + 声学回声消除（AEC）+ 降噪。

方案麦克风配置阵列形态波束/处理特点
Amazon Echo（初代）7 麦（6 环 + 1 中）环形Lab126 专有波束成形 + AEC + NR定义远场标准，S8
Google Nest/Audio多麦（2–3）线性/环形双麦波束 + 深度学习降噪与 Pixel 端侧处理协同，S6/S10
Apple HomePod多麦环形阵列环形自适应波束 + 空间感知与播放声学耦合去回声，S7·推测
百度小度智能屏2–N 麦（带屏）线性/面阵远场波束 + 回放抑制中文远场优化，S9·推测
手机（Android/iOS）2–3 麦贴边线性波束 + 手持降噪近场为主，Siri/Google 共用，S7

工程要点：环形阵列用 TDOA（到达时差）估计声源方位，形成指向性波束；AEC 需与本地播放（音乐/ TTS 回放）对齐以消除「自己听到的自己」；近场手机则更依赖单麦/双麦降噪与手持姿态补偿。

2.3　VAD 与降噪

VAD（Voice Activity Detection，语音活动检测）决定「何时开始/停止录音与计费」，直接影响延迟与云端成本。降噪包含：单麦谱减/深度学习降噪、多麦波束、AEC、风噪与突发噪声抑制。Google 的端侧处理在 100Hz–4kHz 频段做波束以匹配人声（S10）；腾讯云 ASR 宣称对嘈杂环境鲁棒、无需用户预降噪（S5）。

2.4　端侧唤醒模型

端侧唤醒模型通常为轻量 DNN/CRNN 或量化 CNN，参数量在几十 KB 到数 MB，运行在 DSP、MCU 或 NPU 上，常驻功耗控制在毫瓦级。训练依赖海量「唤醒词正样本 + 海量负样本（含相似音、电视声）」以防误唤醒。Apple 的 Hey Siri 模型即在端侧持续运行且不外传音频（S7）；Alexa 的唤醒模型同样端侧运行（S8）。小度/讯飞的唤醒与端侧 ASR 细节未公开，标注为推测。

未公开细节标注（推测）：百度小度与讯飞输入法在端侧唤醒/端侧 ASR 的具体模型结构、参数量、常驻功耗均未披露，本节相关描述基于行业通行做法推断，非厂商公开数据。

三、语音链路流程：录音→传输→ASR→NLU→DM→TTS

一条语音指令的生命周期可拆为六段。本节给出通用流程，并指出各家的优化重点。

  1. 录音与音频流传输：端侧采集（16kHz/8–16bit 常见）→ 端侧预处理（AEC/降噪/AGC）→ 编码（Opus/AMR/PCM）→ 安全上传（HTTPS/gRPC/WebSocket）。
  2. ASR（自动语音识别）：将音频转文本。主流为端到端 RNN-T 或 Transformer，支持流式输出。
  3. 意图理解与语义解析（NLU/语义）：将文本映射为「意图 + 槽位」（如 play_music + {artist:周杰伦}），或交由大模型做自然语言理解。
  4. 对话状态管理（DM/DS）：维护多轮上下文、会话槽位、澄清与确认，决定下一步动作。
  5. 执行与内容检索：调用音乐/天气/日历/智能家居/第三方 Skill 或大模型生成。
  6. TTS 与呈现：文本转语音回放，或返回文本/卡片；端侧神经 TTS 可将首包延迟压到 200ms 内（S7）。

3.2　ASR、NLU 与对话状态管理

ASR 层，Google 明确采用 RNN-T/Transformer 端到端架构，首字响应可控制在 300ms 内（S10，媒体测算）；腾讯云 ASR 基于 Transformer，支持 27 种方言与普/粤/英混合识别，字准率宣称 97%（S5，厂商宣称）；讯飞依托星火大模型与多年语音数据，支持 74 语种/方言免切换（S3）。NLU 层，传统方案用「领域分类 + 意图识别 + 槽位填充」，新一代方案直接用大模型做语义解析与规划（Alexa+、Siri+Apple Intelligence、Gemini、文心）。对话状态管理方面，Alexa 用 Skills 的对话模型 + 会话属性；Google 用 DialogStateOut（见 SDK）维护麦克风模式与上下文（S6）；大模型方案则以会话历史/记忆替代显式状态机。

5.2　封闭平台 vs 开放生态

Apple 走封闭路线：Siri 深度绑定 iOS/macOS，第三方只能通过 App Intents/Extension 有限扩展，隐私与体验一致性强但创新受限。Amazon 走开放路线：AVS（硬件接入）+ ASK（Skills，Lambda/HTTPS）构成最成熟的第三方语音开发生态，Alexa 技能曾超 10 万（S8）。Google 居中：Android 开放但 Assistant 能力受 Google 服务约束；其 SDK 对非商业设备开放、商业设备受限（S6）。百度 DuerOS、腾讯云则面向 B 端开放语音能力。

7.2　未来演进趋势

  • 大模型化：Alexa+（Nova/Claude via Bedrock）、Apple Intelligence（Siri）、Gemini、文心/小度、星火/讯飞、元宝/腾讯，将语音从「指令」升级为「对话式 Agent」。
  • 端侧化：NPU 算力提升 + 小模型蒸馏，使 ASR/NLU/TTS 更大比例在端侧，降低延迟与隐私风险（Apple、Google 已领先）。
  • 多模态：语音 + 视觉 + 屏幕 + 手势融合（如小度带屏、字节 PICO 语音+手势），Siri 2024 起支持图文混合输入。
  • 入口迁移：独立音箱见顶，语音成为手机、车载、可穿戴、家电的「系统级能力」而非独立产品。
  • 个性化与主动服务：从被动响应到主动提醒（老人看护、儿童教育等垂直场景）。
趋势判断（基于公开资料的合理推断，非厂商路线图）：语音交互的下一阶段竞争焦点是「Agent 化能力」与「单位推理成本」，而非唤醒率或识别率——后者已接近天花板。

8.3　竞争格局趋势与演进动因

  • 结构拆解：硬件（低毛利/引流）→ 软件与服务（高毛利/留存）的价值天平持续向「服务端」倾斜；音箱出货下滑但语音 API 调用量随 AI 应用上升。
  • 竞争变量：①大模型能力差距；②端侧算力与功耗；③隐私合规约束（PIPL/GDPR/CCPA）；④生态开放度与第三方开发者；⑤单位推理成本曲线。
  • 演进动因：算力成本下降 + 模型能力提升共同推动「端云协同」再平衡；隐私法规迫使常驻监听类产品收敛数据；AI 助手（而非音箱）成为最终载体，使语音能力「泛在化」。
  • 市场结构变化：智能音箱从「独立增长曲线」退化为「智能家居/手机/车载的附属能力」；输入法因 AI 化重获入口价值；云语音 API（讯飞、腾讯、AWS、Google）成为跨行业的水电煤。
经济学结论：语音交互的「商品化」使硬件利润稀薄，护城河转向「模型 + 数据 + 生态 + 合规」四要素。短期看，拥有大模型与端侧芯片（Apple、Google）或多模态内容生态（Amazon、百度、腾讯）者更易捕获长期价值；纯硬件 OEM 面临被管道化风险。
